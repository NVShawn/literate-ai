# ADR 0058: Publish hierarchical retained-tree information cards

- Status: Accepted
- Date: 2026-11-03
- Acceptance: The directing user explicitly accepted ADRs 0056–0059 for 1.4 on 2026-11-03 ("Accept all four ADRs").
- Decision owners: directing user and literate-ai maintainers
- Release target: 1.4.0
- Roadmap: [RETAINED-TREE-EXPLORER-001](../roadmap/active-work.md#retained-tree-explorer-001-publish-hierarchical-retained-tree-html-information-cards)
- Issue: [#279](https://github.com/jordanhubbard/literate-ai/issues/279)
- Governance: [ADR 0006](0006-significant-feature-request-governance.md)

## Context

The current HTML registry exposes six project views in
`adapters/html_surfaces.py`. Each render request publishes one file through
`html_publication.py`; `html_staleness.py` checks those declared artifacts.
The existing project declaration admits at most 128 requests, provenance admits
256 source bindings, and observability adapters bound their records to 4,096.
Those are useful single-view limits, not a hierarchy for a complete native source
or ports tree. This source audit is not a native scale measurement.

Issue #279 requires a top-level `index.html` and nested directory/unit cards for
real retained source and ports trees. Merely raising the old request limit or
flattening the entire tree into one graph does not satisfy it. Per-unit Component
cards additionally need the exact partition and provenance supplied by #235.

## Decision

### Explicit tree-view declaration and commitments

Add an opt-in, versioned tree-view declaration and manifest family alongside the
existing single-file HTML protocol. Preserve existing request schemas, defaults,
identities and freshness checks. One tree declaration selects an exact retained
input root and its policy, the view/renderer identity, an owned publication target
and finite rendering limits. It does not expand into thousands of authored render
requests or accept an unbounded list of source bindings in one old record.

Reuse canonical retained-tree capture, alias resolution, sharded descriptors and
source-currentness owners. The observed root commits to the complete declared
namespace, including additions and deletions. Capture does not follow directory
aliases into another root or turn an unowned link into another input owner.
Display link topology and refusal/unsupported information truthfully.

Each directory card binds its source coordinate and observation, displayed facts,
ordered child commitments and rendered page bytes. A bounded hierarchical index
commits to every descendant page and asset. Names, membership, topology, payload
identities and child order participate in the root commitment. Partition large
directories into deterministic bounded groups/pages; commit to all groups rather
than truncating children or embedding an unbounded parent record. Shards reuse
canonical content-addressed references and reject missing, duplicate, cyclic,
foreign or ambiguously named members.

Per-unit cards join only actual retained unit definitions, membership and package
provenance from ADR 0052/#235. A directory is not automatically a Component; an
unadmitted partition or package claim is labeled accordingly. Directory-card work
can proceed independently, but the complete goal includes these unit joins and
cannot close before the retained-unit prerequisite is fulfilled.

### Browser behavior and resource policy

Use static HTML, CSS and ordinary relative links. The output remains navigable
with scripts disabled and gains no JavaScript dependency or remote asset fetch.
Visible labels and embedded metadata use the existing safe emitter/escaping
boundaries. Reject external navigations and path escapes outside the declared
artifact generation. Logical source coordinates need not expose host paths.

Cards show only the metadata, descriptions and explicitly bounded excerpts that
were actually captured and displayed. Do not call the result a source browser
unless the corresponding source content is present and usable. A metadata-only
directory card cannot imply whole-file viewing, search or source analysis.

Require explicit finite limits for source entries, descriptor/decoded metadata,
depth, child groups per page, page count, per-page bytes, total generated bytes
and retained generation storage. Reuse existing retained-tree ceilings and retain
the existing 64 MiB single-HTML ceiling; do not silently enlarge old protocols.
Charge aggregate metadata and output before decoding or writing the next bounded
group. Stream source hashing and page production without retaining source payloads
or the entire rendered tree in memory. Over-limit views refuse with the offending
budget and do not publish an apparently complete partial explorer.

### One visible multi-file generation

Rendering is read-only with respect to retained inputs. Publication requires a
separately authorized output owner, safe physical parents and collision checks;
render intent or a historical artifact does not grant write permission. This
includes placing the requested `index.html` at the top of an actual source tree.
Refuse a foreign existing index or generation namespace instead of replacing it.

Stage a complete immutable generation under an owned output namespace on the
same filesystem. Its exact manifest binds all page/asset paths and bytes, with
all child links referring to that generation. Verify its complete closure and
revalidate source/current output custody before exclusive generation publication.
Atomically publish the owned top-level `index.html` last as the commit point,
binding that exact generation. A reader of the old index sees the complete old
generation; a reader of the new index sees the complete new one. Do not claim a
multi-path update is one atomic filesystem rename or overwrite a racing index.

Keep that top-level commit envelope outside the immutable generation manifest
whose digest it names. The actual root-directory card is inside the generation;
the envelope binds and links to it and can display its committed summary. Reopen
the envelope's own exact owned bytes separately. Do not make a manifest hash a
page that in turn embeds that same manifest hash.

If output is inside the observed source root, exclude only the exact independently
owned generated namespace and index under a current complete output manifest.
Foreign additions or edits there refuse; ignore status or a directory name cannot
hide source from capture. Distinguish input freshness from output ownership.

Interrupted publication leaves the previous complete generation visible, or no
initial index, and retains bounded identifiable staging/recovery evidence.
Rollback and later collection affect only exact still-owned nodes; preserve
foreign/concurrent changes. Retain old generations while readers may use them.
Collection requires its own explicit ownership and authorization; render does
not authorize deletion. Refuse when the finite storage allowance cannot retain
the necessary generations, rather than accumulating unbounded output.

### Tree-level freshness and acceptance

Add an additive declared tree-artifact freshness gate. Reopen the exact manifest,
root/child commitments, complete artifact namespace and actual page/asset bytes;
then reobserve the selected retained tree through canonical currentness owners.
Changed source, child links, page bytes, renderer, unit partition or unexpected
output members makes the tree stale. A valid saved manifest is evidence, not live
source or publication authority. Existing single-file gates keep their meaning.

Qualify an installed non-editable wheel on real native source and ports trees,
including the actual `/usr/src` and `/usr/ports` use case. Retain measured entry,
directory and page counts, output bytes, wall time and peak memory. Inspect the
actual browser output with scripts disabled, top-level and nested navigation,
large-directory pagination and truthful directory/unit labels. The issue's
inventory figures are planning inputs, not that qualification.

Exercise source/alias drift, stale or foreign unit joins, edited/missing children,
unexpected members, resource boundaries, foreign destinations, concurrent writers,
interruption before/after index publication and incomplete recovery. Renew legacy
single-file positives/refusals, independent source review, full integrated gates
and exact-commit native qualification before closing the 1.4 goal.

## Consequences

One declaration can describe a complete retained-tree explorer without weakening
small-view limits or source custody. A generation manifest and one index commit
point add ownership, storage and recovery obligations. All #279 requirements,
including per-unit cards after #235, remain in 1.4. The directing user accepted this
design under ADR 0006 on 2026-11-03; implementation and qualification remain open.
