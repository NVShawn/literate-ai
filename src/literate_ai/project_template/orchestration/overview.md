# Repository orchestration authority

<!-- literate-ai:authority-review-pending -->

The root project manifest binds configured child names, paths, URLs, branches and
exact Gitlink commits, the indexed `.gitmodules` content identity, and explicit
consumer/provider relationships. Children are not inherited root catalogs.

Local checkout location, child initialization state and current child HEAD are
observations in a reviewed orchestration plan, not persistent root authority.
Equivalent clean clones can retain the same persistent binding. Local availability
does not establish remote publication or independent acceptance.

Only root-owned onboarding and metadata are created by this profile. Existing
root source, Git metadata and child repositories must remain untouched. There is
no generated Component, lifecycle driver, fabricated test receipt or automatic
child build. Initialization is not root lock/graph integration or reviewed re-pin
qualification; those capabilities require their own current evidence.
